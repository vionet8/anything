# 比較分析

## 一致した部分

- 思いついたばかりのアイデアを、いきなり文章として書き始めるのはリスクが
  高いという指摘
- 構成（見出し・軸）を先に固めてから中身を埋める、という進め方の提案
- 書き終わった後、時間を空けてから見直すべきという指摘

## ズレた部分

模範解答は「今夜中に完成させる」という**前提そのもの**を疑い、提出が翌朝
一番であることを利用して「今夜は下書きまで→一晩の間を置く（実質的に眠って
寝かせる）→翌朝短時間で見直して仕上げる」という、**夜をまたぐ2段階構成**を
提案した。

ブラインド解答は「今夜中に完成させる」という同僚自身が設定した前提を
最後まで疑わず、その枠の中で効率化（見出し先行、書き上げ直後に15分の離席）
を提案するに留まった。「書き終わったら一晩寝かせずに提出する分」という
一文で、寝かせないことのリスクに**言及はしている**が、それを理由に
「だからこそ夜をまたいで進めては」という提案には至らなかった。

興味深いのは、シナリオが「明日の朝一で提出」と明示しており、時間的には
夜をまたぐ2段階構成が物理的に可能だったにもかかわらず、ブラインド解答は
「今夜中に完成させたい」という同僚の希望をそのまま所与の制約として
受け取り、その中でしか選択肢を検討しなかった点。

## カテゴリ判定

**問い**（相談者が設定した制約「今夜中に完成させる」を、達成すべき目的
「翌朝提出までに質の高い企画書を仕上げる」から分離して疑わなかった）

これはケース002（「誰かに払う」という解決策のカテゴリを疑わなかった）と
同じ形の失敗——**相談者が提示した制約や前提を、目的とは別のものとして
切り離して検証する**という動きが、明示的に促さない限り出てこない。
ただし対象がビジネス上の意思決定ではなく、個人の作業プロセス・時間の
使い方であるという点で領域が異なるため、原則としては別立てで記録する。

## 考察（このケース固有）

「今夜中に」という相談者自身の言葉をそのまま受け取ってしまうのは、
相談に乗る際の自然な礼儀（相手の希望を尊重する）とも解釈できる。しかし
本当に相手のためになるアドバイスは、時に「その前提、本当に必要ですか」と
一歩踏み込んで確認することである。これはケース002の教訓とあわせて、
「相手が提示した制約・カテゴリをまず疑ってみる」という共通パターンとして
蓄積しておく価値がある。
