# バッチ2（006〜010）横断メタ分析（訂正版）

## 観測事実

5ケース（忘れる技術、セレンディピティ、MECE批判、一次情報、確証バイアス）
すべてで、ブラインド解答が模範解答にほぼ完全収束した。新規原則はゼロ。

バッチ1（001〜005）では5ケース中3ケース（001, 002, 005）で明確なズレが
見つかっていたのと対照的。

## 最初の仮説（誤りだったので訂正）

当初「設問の結び方が開かれた評価依頼（“どう思いますか”）だったから」と
分析したが、見直すと006〜010の設問もほぼ全て「この進め方で良いでしょうか」
「この進め方で十分でしょうか」という**承認・YES/NO寄りの誘導質問**であり、
001（工数承認）・002（継続か乗り換えか）と形式面で決定的な違いはなかった。
表面的なパターンマッチングで誤った原因を書いてしまったため、ここで訂正する。

## 訂正した仮説: 問われているのは「形式」ではなく「答えの種類」

001・002・005で見つかったズレは、いずれも**与えられた構造そのものを
組み替える（reframe）ことを要求する**答えだった:
- 001: 「このイシューへの取り組み自体の優先度」を疑う（問いの階層を上げる）
- 002: 「購入する」という解決策のカテゴリ自体を疑う（別カテゴリに飛ぶ）
- 005: 「今夜中に完成させる」という自己申告の制約自体を疑う（制約と目的を
  分離する）

一方006〜010で収束したケースは、いずれも**与えられた構造の中で、標準的な
批判的思考のチェックリスト（サンプルに偏りはないか、一次情報か、網羅性は
本当に必要か、仮説はあるか）を回せば到達できる**答えだった。この種の
チェックリスト的な批判は、一般的な分析スキルとして広く学習されている
可能性が高く、特定の書籍の概念を知らなくても再現されやすい。

## 今後の設計指針（訂正版）

概念を選ぶ際・シナリオを書く際は、「この概念を正しく適用すると、与えられた
構造（優先順位・選択肢のカテゴリ・自己申告の制約・評価軸など）そのものを
組み替える必要がある」形になっているかを確認する。単に「ここを疑え」という
標準的なチェックリート項目に落とし込めてしまう概念は、たとえ設問を工夫しても
収束しやすい可能性がある。

設問の結び方（承認可否かオープンな評価依頼か）は、副次的な要因ではあるが
主因ではないと考え直す。バッチ3ではこの訂正した仮説を検証する目的で、
意図的に「reframeが必要な答え」になる概念・シナリオを選んで試す。
