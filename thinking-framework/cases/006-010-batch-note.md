# バッチ2（006〜010）横断メタ分析

## 観測事実

5ケース（忘れる技術、セレンディピティ、MECE批判、一次情報、確証バイアス）
すべてで、ブラインド解答が模範解答にほぼ完全収束した。新規原則はゼロ。

バッチ1（001〜005）では5ケース中3ケース（001, 002, 005）で明確なズレが
見つかっていたのと対照的。

## 仮説: 原因は概念の難易度ではなく、設問の「形式」

バッチ1でズレが見つかったケース（001, 002, 005）は、すべて**狭い具体的な
決定・二択を迫る形式**だった:
- 001: 「工数承認の可否についてコメントを求められている」
- 002: 「継続すべきか、A社に乗り換えるべきか」
- 005: 「効率よく今夜中に完成させるには、どう進めるのがいいと思う？」

バッチ2で収束したケース（006〜010）は、すべて**「このやり方どう思います
か」という開かれた評価依頼**の形式だった。

この形式の違いが結果を左右した可能性が高い。開かれた評価依頼は、それ自体が
「相手の前提を疑ってよい」という許可・誘発になっており、ブラインド解答者は
自然に批判的思考モードに入る。一方、具体的な二択・承認可否を尋ねる形式は、
「その枠の中で答えるべきだ」という暗黙の圧力を生み、枠自体を疑う動きが
起きにくくなる。

## 結論と今後の設計指針

**このプロジェクトが検出しようとしている「枠を疑えない」という失敗は、
概念そのものの理解度の問題というより、質問の形式によって誘発されたり
抑制されたりする現象である可能性が高い。**

したがって今後のケース設計では、次の2点を徹底する:

1. シナリオの結びは、「どう思いますか」ではなく、**具体的な二択・承認可否・
   YESかNOかを迫る形**にする（バッチ1の001, 002, 005のパターンを踏襲）。
2. 相談者自身が既に何らかの結論・計画を持っていて、それに対する「賛成/
   反対、あるいはこのまま進めていいか」を聞く形にする（「この方針で
   問題ないでしょうか」ではなく「これで進めます、意見をください」に近い
   圧力をかける）。

`.claude/skills/case-study/SKILL.md` にこの指針を反映する。
