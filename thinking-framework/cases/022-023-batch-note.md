# バッチ横断: コルブ vs FPRL／予測符号化理論 vs FPRL

前回（cases/021）はFPRLと熟達論が「同じ結論に収束する」パターンだった。
今回は逆に、**理論同士が異なる予測・異なる診断を出す場面**を狙って
シナリオを設計した。

## ケース022: コルブ vs FPRL（振り返りはしているのに行動が変わらない）

| | コルブの経験学習理論 | FPRL |
|---|---|---|
| 診断の軸 | サイクルの4段階（経験・内省・概念化・実験）のどこが欠けているか | 4つの停滞パターン（検知・解釈・更新・熟達）のどこで止まっているか、特にゲート（E₁〜E₃）のどこが閉じているか |
| 今回の診断 | 「能動的実験」が欠けている。対策を次回に実行として結びつける仕組みがない | 「更新停滞（L）」。理解（R）は既に完了しているのに、受容ゲート（E₃）が閉じている |
| 処方箋 | サイクルを閉じる仕組み（実行チェック）を足す | E₃が開く3条件（必要性・整合性・コスト許容）のどれが欠けているかを診断する。特に心理的抵抗（自己防衛）を疑う |
| 弱み | なぜサイクルが止まるのか（心理的抵抗など）の説明機構を持たない | 手順として何を足せばいいかの具体性は、コルブほど明快ではない |

**一致点**: どちらも「言語化・反省の精度を上げること」では解決しない、
という診断は共通していた。

**相違点**: コルブは「サイクルの欠けている段階を埋める」という手続き的な
処方箋を出すのに対し、FPRLは「なぜ変わらないか」を心理的抵抗まで含めて
説明しようとする診断的な処方箋を出す。コルブのモデルは「分かっている
のに変われない」という現象そのものを直接は扱えない（4段階のどこかが
「欠けている」という説明にしかならない）が、FPRLは理解の完了と受容を
明確に別ゲートとして分離しており、この現象を名指しで扱える。

## ケース023: 予測符号化理論 vs FPRL（大きく明瞭な誤差を無視され続ける）

| | 予測符号化理論 | FPRL |
|---|---|---|
| 基本原理 | 予測誤差が大きいほど、更新への駆動力が強くなる | 差分の大きさと、それが受容されるかどうかは別軸。規範的評価軸（自己にとって脅威かどうか）が別途存在する |
| 今回のケースへの予測 | 誤差はすでに大きく明瞭なので、理論上は強い更新圧力がかかっているはず。伝達経路のどこかに問題があると考える | 大きく明瞭な誤差（特に自己像を脅かす種類の差分）を繰り返し当てることは、防御反応を強化し、むしろ更新を遠ざける可能性がある |
| 「もっと繰り返し、もっと分かりやすく」への含意 | 理論上は有効なはずの手段（誤差信号を強める）が効いていない、という不整合が生じる | 理論的に効かないどころか逆効果になりうると明示的に予測する |

**一番の発見**: 予測符号化理論を素直に適用すると「誤差信号を強めれば
いずれ更新されるはず」という、相談者の当初の方針（もっと繰り返し・
分かりやすく）を肯定する方向に働きかねない。FPRLは、規範的評価軸
（自己防衛）という追加要素によって、**同じデータ（大きく明瞭な誤差が
無視されている）から正反対に近い処方箋（信号を強めるのをやめる）を
導いた**。これは本文中でFPRLが自ら「予測符号化理論と近いが、規範的
評価軸を含む点で異なる」と述べている差別化ポイントが、実際のケースで
具体的な予測の違いとして表れた例になっている。

## まとめ

2件とも、ブラインド解答（本を知らない素の判断）はFPRLの結論に近い
ところまで独立に到達しており、単体では新規原則を生まなかった。しかし
**理論同士を直接比較する**というこのアプローチ自体は、cases/021の
「収束による裏付け」とは違う種類の価値を生んだ。特にケース023は、
2つの理論が同じ観測データから逆方向の処方箋を導く実例であり、
FPRLが予測符号化理論に対して主張する差別化ポイント（規範的評価軸）が
単なる定義上の違いではなく、実際の意思決定を変える違いであることを
示している。
