# 比較分析

## 一致した部分

- 金額差（年間72,000円）と乗り換えコスト（データ移行・保護者対応の手間）を
  天秤にかけて考えるべき、という基本姿勢
- 「同じようなサービス」を額面通りに同一視せず、機能・サポート体制の実質的な
  同等性を確認すべきという指摘
- 「今すぐ二択で決める必要はない」という結論の柔らかさ

→ ブラインド解答は「与えられた二択（継続/乗り換え）」に対して**第3の選択肢
（現ベンダーとの値下げ交渉）を自力で追加**しており、単純な二択思考ではなかった。
これはケース001の教訓（与えられた枠の中での検証はできる）を上回る健闘で、
「枠の中で選択肢を増やす」動きまではできることを示した。

## ズレた部分

ただし、追加された第3の選択肢（値下げ交渉）も含めて、ブラインド解答は
一貫して**「誰かに月額利用料を払い続ける」という同じ種類の解決策**の中で
選択肢を検討している。

模範解答が導入したのは、選択肢を増やすことではなく、**検討している解決策の
「カテゴリ」自体を疑う**動きだった。「出欠管理・月謝請求・一斉連絡」程度の
機能を提供するのに、そもそも継続的な利用料を誰かに払う必要が今の技術水準でも
本当にあるのか（AIでの自前構築という、購入ではないカテゴリの解決策が
現実的な選択肢になっていないか）という問い。

ブラインド解答が「同じようなサービスだが同一ではない」という慎重さを見せた
一方で、「そもそも“サービスを買う”という前提自体、技術の進歩で崩れているのでは」
という、もう一段階外側の疑いには至らなかった。

## カテゴリ判定

**問い**（検討している解決策の集合が、暗黙のうちに「購入」というカテゴリに
限定されており、そのカテゴリの外にある解決策の存在に気づいていない）

ケース001が「そもそもこの問題に取り組むべきか」という優先順位の問いだった
のに対し、本ケースは「そもそも今検討している解決策の種類（誰かから買う）が
唯一の選択肢なのか」という、解決策の空間の広さに関する問い。関連するが
別の失敗パターンとして記録する価値がある。

## 考察（このケース固有）

「選択肢の中で比較検討する」「選択肢を1つ追加する（値下げ交渉）」までは
一般的な批判的思考でも強く出てくる。しかし「そもそも提示された選択肢群が
属するカテゴリ自体が、技術的な前提の変化（AIによる低コスト自前開発の実現）
によって崩れていないか」を疑う動きは、明示的に促さない限り出てこない。
これは新しい技術トレンド（今回で言えばAIによるコード生成）への感度が
特に必要な種類の「問い」の見落としであり、書籍ベースのケース（001）とは
異なる角度の同種の失敗として記録する。
