# 思考フレームワーク蓄積プロジェクト

思考法の名著（例: 外山滋比古『思考の整理学』、安宅和人『イシューから始めよ』など）の
概念を、対話の中で「知識として説明できる」状態から「実際の判断に反映される」状態へ
近づけるための実験的な仕組み。

## 目的と限界（先に書いておく）

このリポジトリの目的は「本を読んだふりをする」ことではなく、以下を機械的に繰り返すこと。

1. 本の概念を試す具体的なケース（シナリオ）を作る
2. **その概念を知らない状態**でケースに答えを出す（＝素の判断）
3. 本の立場に基づいた「模範解答」と突き合わせる
4. ズレの正体を「状況 → 誤り → 原則」の形で `principles.md` に積み上げる

重要な限界:

- ステップ3の「模範解答」は、ユーザーが実際の本文抜粋を提供しない限り、
  Claude自身の知識に基づく**要約・再構成**であり、本文そのものではない。
  複数の本の概念が混線したり、細部が不正確な可能性がある。
  各 `answer.md` には根拠の質を `grounding: quote | paraphrase` で明記する。
  精度を上げたい概念については、本文抜粋・該当ページの画像/PDFを渡してほしい。
- ステップ2の「知らない状態」は、Claude Codeの `Agent` ツールで生成した
  **文脈を持たない新規エージェント**に、ケース文だけ（本の名前や概念名は伏せて）
  渡すことで実現している。同じモデルではあるが、会話履歴を共有しないため、
  「答えを書いた直後にその答えを演じる」という自己参照は避けられる。
  ただし別モデル・別人間による解答ではないため、統計的な癖（学習データの中央値的発想）
  は残る。

## ディレクトリ構成

```
thinking-framework/
  README.md          このファイル
  ROUTINE.md          実行ペース配分・トークン予算の計画（新セッションはまずこれ）
  backlog.md           本ごとの概念一覧と進捗状態（未着手/実施中/収束/要検証）
  usage-log.md         バッチごとの実測トークン消費ログ
  principles.md       積み上がった「状況→誤り→原則」の一覧（本体）
  cases/
    001-xxx/
      case.md          シナリオ本文（本の名前・概念名は伏せる）
      answer.md         本に基づく模範解答（grounding明記）
      prediction.md      文脈を持たないAgentが書いた素の解答
      diff.md            予測と模範解答のズレの分析
```

新しいセッションでこのプロジェクトを再開するときは、`ROUTINE.md` →
`backlog.md` → `principles.md` の順で読めば、それまでの会話を覚えていなくても
続きから着手できる。

## ワークフロー（現状: 手動トリガー）

`.claude/skills/case-study/SKILL.md` にワークフローを実装済み。
Claude Codeのセッションで `/case-study <本のタイトルか概念>` のように依頼すると、
1本分のケースを一通り生成・実行して `principles.md` を更新する。

自動化（`/loop` での定期実行など）は品質を数回確認してから検討する方針。
現時点ではまず数回手動で試し、`answer.md` の根拠の質や `principles.md` に
積み上がる原則が実用に足るかを見極める。

## 15ケース時点での暫定的な発見（2026年9月時点）

`cases/011-015-batch-note.md` に詳細があるが、要点だけ書いておく。

「相手の計画を評価・批評してください」という形で明示的に頼まれたとき、
ブラインド解答は15ケース中10〜11ケースで模範解答にほぼ完全収束した。
新しい原則が生まれた（明確なズレが見つかった）のは3ケースのみ
（約20%）で、概念の種類・設問形式のどちらを工夫しても、ズレの有無を
事前に予測する変数はまだ見つかっていない。

これは当初の問い（「思考法の名著を重み付けすれば凄いパフォーマンスが
出るのでは」）への暫定的な答えでもある: 批評を明示的に求められた場面
では、モデルは既に本の教えのかなりの部分を自力で再現できており、劇的な
向上余地は限定的そうだった。一方で見つかった3つの原則は、いずれも
「相手が置いた前提の外側に出る」種類の、実務上価値の高いズレだった。
量は少なくても質的には無視できない。

## principles.md の使い方

蓄積された原則は、他のClaude Codeセッションの `CLAUDE.md` や
システムプロンプトから参照することで、実際の判断に反映させることを想定している。
定期的に重複エントリの統合・陳腐化した原則の削除を行うこと（増えすぎると
かえってノイズになる）。
